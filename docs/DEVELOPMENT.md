# CCUH 개발 체크리스트

사용자가 Computer Use에 작업을 맡기면 CCUH가 자동으로 연결되어, 허용된 앱과 창에서 사용자 작업을 방해하지 않고 실행하는 것이 목표입니다. 카카오톡, 메모와 Chrome은 시험 예시이며 특정 앱에 한정하지 않습니다.

## 현재 위치

**현재는 1.3 다른 도구에서 미실행 확인을 진행합니다.** 최소 수신 훅의 복구와 두 지원 도구의 실제 자동 수신을 확인했습니다. 앱 조회, 창 조작과 네이티브 엔진은 아직 없습니다.

앞서 브라우저 목록 호출의 수신을 Computer Use 외 실행의 증거로 판단한 것은 정정합니다. 브라우저를 다뤘다는 사실만으로 플러그인 밖의 호출이라고 판단할 수 없습니다. 공유 도구명만으로 사용자가 선택한 플러그인을 증명할 수도 없으므로, 실제 호출 범위는 1.2와 1.3에서 확인합니다.

## 진행 방법

- 한 번에 체크 한 항목만 진행하며 **개발 → 검증 → 리팩토링 → 재검증 → 커밋**까지 마친 뒤 넘어갑니다.
- 체크는 해당 소스와 실제 설치본에서 완료 조건을 확인했을 때만 표시합니다. 과거 검증이나 합성 입력 검사를 현재 설치본의 성공으로 옮기지 않습니다.
- 정상 Computer Use 호출에서는 자동 연결하고, 일반 코딩, 셸, 검색과 다른 MCP 호출에서는 실행되지 않아야 합니다. 브라우저 작업을 일괄 제외하지 않습니다.
- 앱 접근 제한과 필요한 승인 및 OS 권한을 유지합니다. 수동 직접 실행이나 위조 입력 방어는 별도 보안 항목이며, 정상 호출의 자동 연결 검증과 구분합니다.
- 검증은 가능한 범위에서 자동화합니다. 사용자 확인이 꼭 필요한 경우에만 이유와 필요한 행동 하나를 알립니다.

## 1. Computer Use 자동 연결

- [x] **1.1 최소 수신 훅 복구** — 수신 훅 하나만 등록하고 실제 로드된 설정과 설치본 소스가 개발본과 일치하는지 확인합니다. 필요한 훅 신뢰 승인은 사용자가 직접 합니다.
  - 검증한 소스와 설치본: 로컬 `0.0.0`, 수신기 해시 `a7eb0d63a9ed533966f76ee0551a6cdaf5d25ce7d72f477fc14922c7b4224428`.
  - 관측 방법과 결과: 공식 `hooks/list`에서 PreToolUse 1개와 `trusted`, 개발본과 설치본의 설정, 진입점 및 소스 일치를 확인했습니다. 타입, 훅 문법, 포맷과 매처 검사 14건도 통과했습니다.
- [x] **1.2 실제 자동 실행 확인** — 지원 대상으로 등록한 Computer Use 도구를 실제로 호출하고 수신기 시작과 새 수신 기록을 대조합니다. 별도 CCUH 도구 선택이나 수신기 직접 실행은 성공 증거로 사용하지 않습니다.
  - 검증한 소스와 설치본: 1.1과 같은 `0.0.0` 및 수신기 소스. 별도 CCUH 도구나 수신기 직접 실행 없이 두 실제 도구를 호출했습니다.
  - 관측 방법과 결과: `js` 호출 뒤 `2026-11-01T18:12:08.179Z`에 receipt `fa589c14-202e-496e-93c7-d5603e142c9e`가 생성됐고 코드 및 소스 해시가 일치했습니다. `js_reset` 뒤 `2026-11-01T18:13:47.651Z`에 receipt `0f4ea791-28eb-4964-a8c3-712749232dc9`가 생성됐고 도구명, 코드 해시 없음 및 소스 해시가 일치했습니다. 앱이나 창을 조작하는 호출은 하지 않았습니다.
- [ ] **1.3 다른 도구에서 미실행 확인** — 일반 코딩, 셸, 파일 수정, 검색과 다른 MCP를 실제로 호출해 CCUH 수신기 실행 시작이 없는지 확인합니다. 수신 기록 불변만으로 프로세스 미실행을 판정하지 않습니다.

**다음 단계 조건:** 같은 설치본에서 1.2의 자동 실행과 1.3의 제외가 함께 확인되어야 합니다. 다른 경로가 같은 도구를 공유해 구별되지 않으면 그 경로를 미확인으로 남기며 전용 실행이 보장됐다고 하지 않습니다.

## 2. 앱 접근 제한과 사용자 작업 보호

- [ ] **2.1 허용한 앱만 접근** — 같은 작업의 앱 허용, 승인 대기와 거부를 구별하고 거부된 앱에는 조회나 동작을 보내지 않습니다. 앱 목록이나 창 제목을 접근 허용으로 해석하지 않습니다.
- [ ] **2.2 사용자 화면과 입력 대상 유지** — 첫 호출부터 종료까지 화면, 전경 앱과 키보드 입력 대상을 관측합니다. 같은 데스크탑과 다른 데스크탑, 전체화면, 여러 모니터에서 사용자가 작업을 계속할 수 있어야 합니다.
- [ ] **2.3 오류에서도 보호 유지** — 권한 거부나 오류가 나면 중단하고 즉시 알립니다. 다른 도구, 앱 활성화나 전경 키보드 및 마우스 조작으로 우회하지 않습니다.

**다음 단계 조건:** 접근 제한과 사용자 포커스가 시작, 실행, 실패와 정리 과정에서 유지되어야 합니다. 사용자 조작과 AI의 간섭을 구별하지 못한 관측은 미확인으로 둡니다.

## 3. 작업할 앱과 창 찾기

- [ ] **3.1 지정한 앱과 창 조회** — 사용자의 전경 창을 자동 선택하지 않고, 포커스를 옮기지 않은 채 지정한 앱과 창을 읽기 전용으로 찾습니다.
- [ ] **3.2 여러 창 구별** — 같은 제목, 부분 목록, 다른 데스크탑, 최소화와 복원 조건에서 정확한 창을 구별합니다. 후보가 모호하면 중단합니다.
- [ ] **3.3 같은 대상 유지와 연결 해제** — 사용자 화면 전환에도 대상을 유지하고, 창 닫기와 앱 종료 및 식별자 재사용 시 기존 연결을 무효화합니다. 새 창에 자동 재연결하지 않습니다.

**재조회 조건:** 작업 재개, 대상 상태 변경, 예상과 다른 관측이 있을 때만 필요한 정보를 다시 읽습니다. 조건 변화 없이 같은 실패를 반복하지 않으며 서로 다른 도구의 창과 요소 식별자를 혼용하지 않습니다.

## 4. 백그라운드에서 실제 동작

- [ ] **4.1 지정한 창의 내용 읽기** — 확보한 대상 참조로 내용을 읽고 실제 창의 값과 대조합니다. 사용자의 입력 대상은 유지되어야 합니다.
- [ ] **4.2 지정한 입력란 수정** — 자체 시험 앱의 입력란 하나를 변경하고 실제 값과 실행 횟수를 확인합니다. 보안 입력란, 비활성 요소와 오래된 참조는 거절합니다.
- [ ] **4.3 버튼 실행과 결과 확인** — 자체 시험 앱의 버튼 하나를 실행하고 별도 상태 변화로 성공을 확인합니다. 불확실한 전송이나 저장을 자동 반복하지 않습니다.

**다음 단계 조건:** 올바른 대상, 한 번의 실행, 실제 결과와 사용자 작업 비간섭을 함께 확인해야 합니다. 값 변경을 메시지 전달이나 저장 완료로 보고하지 않습니다. 자체 시험 앱 이후 필요한 외부 앱 사례를 검증합니다.

## 5. 전체 흐름과 배포 검증

- [ ] **5.1 요청 하나로 전체 흐름 연결** — Computer Use 요청 하나로 자동 연결, 대상 찾기와 동작 완료까지 수행합니다. 별도 CCUH 도구 선택 없이 앞 단계의 제한을 모두 유지해야 합니다.
- [ ] **5.2 동시 작업과 실패 처리 검증** — 사용자 동시 작업, 취소, 시간 초과, 연결 끊김, 권한 철회와 앱 종료를 확인합니다. 재시도를 제한하고 종료 후 소유한 세션과 프로세스를 정리하며, 재시작 후 오래된 참조를 재사용하지 않습니다.
- [ ] **5.3 설치본 검증과 릴리스** — Codex App과 CLI의 지원 경로를 각각 검증하고 개발본과 설치본의 실행 경로를 대조합니다. 해당 버전의 CI, 태그와 릴리스 결과까지 확인합니다.

**완료 조건:** 연결 성공, 훅 실행, UI 변화와 실제 업무 완료를 구분해 보고합니다. 검증하지 못한 환경을 지원 완료로 표시하지 않습니다. 릴리스 운영 방법은 [README](../README.ko.md#릴리스)를 따릅니다.
